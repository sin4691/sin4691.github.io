GitHubAPK

벨트를 앞에 이어 붙이면 아이템이 멈춰 보이던 버그

문제 리스트 순서가 곧 처리 순서라고 가정했는데, 기존 벨트 앞쪽에 새 세그먼트를 이으면 리스트 뒤에 붙지만 실제로는 상류입니다. 경계에서 한 틱씩 낡은 상태로 판단해 아이템이 멈춘 것처럼 보였습니다.

해결 배열 순서를 믿지 않고 NextSegmentId를 따라 후위 순회 DFS로 처리 순서를 계산해 하류부터 처리합니다. 초기 구현 중에 발견했고, 상류·하류를 일부러 반대로 넘기는 테스트와 함께 고정했습니다.

// BeltSystemTests.cs — 상류를 리스트 뒤에 두고도 하류로 넘어가는지
var segments = new List<BeltSegment> { downstream, upstream };
for (int i = 0; i < 20; i++) system.Tick(0.05f, segments, processors, null);
Assert.AreEqual(0, upstream.Items.Count);
Assert.Greater(downstream.Items[0].Position, 0f);
대형 공장 렉 추적 — 11~15 FPS → 30 FPS(상한)

문제 벨트 1,455칸·설비 904개 테스트 공장에서 FPS가 11~15로 떨어졌습니다. Profiler에서 프레임 비중이 큰 항목부터 하나씩 원인을 찾았습니다.

① 벨트 경로 캐시 32.6% → 1.5% 캐시(71e8e2a)는 있었지만 값이 같아도 무효화되는 조건이었고, 전력 시스템이 0.2초마다 모든 기계의 레시피를 같은 값으로 다시 넣어 캐시가 1초에 5번 버려지고 있었습니다. 값이 실제로 바뀔 때만 무효화하도록 고쳤습니다.

②~④ 팀원 담당 코드의 병목 전력 계산 16.9%(기계마다 송전탑·전선 전체 재검색 → 한 번만 수집), HUD 34.3%(매 프레임 씬 전체 검색 → 참조 캐싱), 기계 상태 표시 12.5%(매 프레임 재배치 → 바뀔 때만 갱신).

측정 조건 Unity 에디터 Play Maximized, 같은 공장에서 수정 전·후 비교. 비율은 프레임 전체 대비입니다.

풀링·뷰포트 컬링 — 켬/끔 스위치로 효과 검증

아이템 슬롯 풀 흐르는 아이템 표시물을 생성·파괴하지 않고 슬롯을 재사용합니다. 풀 끔/켬 3회 평균 PlayerLoop 47.2 → 40.7 ms(−14%), GC 333 → 284 KB/프레임(−15%). 조건: 공장 전체가 보이는 화면, 아이템 약 1,155개.

뷰포트 컬링 화면 밖 청크의 비주얼을 꺼서 스크립트까지 멈춥니다. 공장 99.8%가 화면 밖일 때 PlayerLoop 30.1 → 16.8 ms(−44%), 약 17%일 때 34.9 → 32.7 ms. 효과는 화면 밖 스크립트 정지(LateUpdate 12.3 → 1.3 ms)에서 나오며, 생산 시뮬레이션은 화면 밖에서도 계속 돕니다.

측정에서 배운 점 처음 경과 시간으로 잰 "59% 감소"는 에디터 Hierarchy 갱신 비용이 섞인 착시여서, Profiler의 PlayerLoop 기준으로 다시 쟀습니다.

벨트 정체(clog)와 철거 후 재연결이 안 되던 버그

구리가 벨트를 막아 철판이 못 지나가던 문제는 라인별 담당 자원을 고정해 해결했습니다. 벨트를 지워도 바로 앞 벨트가 지워진 칸을 계속 '다음 칸'으로 가리켜 그 자리에 새 벨트를 이을 수 없던 문제는, 철거할 때 그 참조(NextSegmentId)를 지우고 같은 상황을 재현하는 테스트로 고정했습니다(07f8227). 인덱스가 밀리지 않게 삭제는 null 슬롯(톰스톤)으로 처리합니다.

손가락에 가려지지 않는 건설 조작

BuildInputRouter가 1터치는 건설, 2터치는 카메라로 나누고 두 번째 손가락이 닿으면 진행 중인 건설을 취소합니다. 기계는 손가락 위로 150px 띄운 반투명 고스트로 보여 주고, 확인 버튼을 눌러야 배치되며 놓을 수 있는지를 색으로 미리 보여 줍니다.

  • 토폴로지 버전이 전역 static이라 테스트끼리 상태가 섞일 수 있어 월드 인스턴스로 옮겨야 합니다.
  • 고정 틱 누적기에 상한이 없어 프레임이 크게 밀리면 더 밀리는 위험이 있습니다.
  • CI가 없어 게임 규칙이 바뀐 뒤 테스트 6개가 깨진 채 남아 있었습니다. 모두 고쳐 팀 전체 65개가 통과하며, 다음에는 CI로 자동 실행하겠습니다.
  • 성능 수치는 모두 에디터 기준이라 실기기 측정이 다음 과제입니다.

GitHubSteam

난이도 의견 충돌을 플레이 테스트로 풀기

문제 저는 난이도를 낮춰야 한다고 봤고, "지금도 낮다"는 의견과 중립도 있었습니다. 협동·트롤·퍼즐·컨트롤이 겹치고 실수하면 뒤로 가는 구조라 피로도가 높습니다.

데이터 서로 겹치지 않는 약 40명(제가 진행한 20명, 팀원 약 12명, 같은 교육과정 다른 두 팀 8명)을 테스트했습니다. 숙련자는 엔딩을 2시간 안에 봤지만, 일반 플레이어는 챕터 2까지만 약 2시간이 걸렸고 챕터 3 초반에 "너무 지친다"며 그만뒀습니다.

결과 타깃은 협동 게임을 좋아하는 일반 4명이고, 한 명이 그만두면 4명이 함께 이탈·환불할 수 있다는 점을 근거로, 메인은 쉽게 두고 엔딩 뒤 매우 어려운 Ex 1~2를 추가하기로 합의했습니다. Ex 맵과 체크포인트 없는 버전 씬을 제가 맡았습니다.

사운드 코드 정리와 예측 점프 소리 중복

점프·피격·발소리마다 복사돼 있던 재생 코드를 PlayerSoundUtility.PlayPositional 하나로 모으고 클립은 ScriptableObject로 뺐습니다. 옵션의 Master 믹서 그룹을 기본 출력으로 등록해 모든 효과음이 볼륨을 따르게 했습니다. 점프 연타 시 소리가 여러 번 나던 건, 클라이언트 예측 재생 뒤 서버 상태가 오기 전까지 코요테 타이머가 다시 채워지던 것이 원인이라 예측 재생 시점에 타이머를 소모하게 했습니다.

플레이어가 하얗게 나오던 네트워크 버그 (팀원 코드 수정)

끊긴 접속의 connectionId가 색상 번호를 계속 쥐고 있어 빈 번호가 없으면 -1이 배정됐습니다. 배정 전에 NetworkServer.connections와 대조해 죽은 ID를 정리하고, 그래도 없으면 connId % 4로 대체했습니다. 원 작성자는 팀원입니다.

GitHub

빌드에서만 나던 한글 UI 크래시

문제 에디터에서는 정상인데, 빌드에서 강화 창(카드 6장)처럼 한글을 한꺼번에 출력하면 앱이 강제 종료됐습니다.

원인 분석 에디터에서는 나지 않고, 빌드에서 한글을 한꺼번에 처음 출력하는 순간에만 재현됐습니다. 그래서 실행 중에 글리프를 즉석 생성하는 TMP Dynamic 폰트로 원인을 좁혔습니다.

해결 상용 한글 2,350자 + 영문·특수문자, 총 2,469 글리프를 2048×2048 Static 아틀라스에 미리 구웠습니다(8afc940). 같은 빌드에서 재현되지 않음을 확인했고, 2,350자 밖 글자는 표시되지 않는 대가가 있습니다.

닿으면 이동하던 문을 "가까이 가서 누르면 이동"으로

문이 보상 선택지가 되면서, 지나가다 닿기만 해도 원치 않는 방으로 넘어갈 수 있었습니다. 트리거는 "근처에 있다"만 등록하고 이동은 입력이 결정하게 나눴고, 떠날 때는 자기 자신이 등록된 문일 때만 해제하며, 사망·부활 중 입력은 무시합니다. 이후 팀원이 보상 줍기를 같은 패턴으로 구현했습니다. 원래 Door는 팀원 코드입니다.

Git 인코딩 문제 — 규칙은 "적용되는지 확인"까지가 한 단계

바뀐 게 없는 코드가 계속 diff로 잡혔습니다. Visual Studio 인코딩을 UTF-8로 통일하고 줄바꿈은 .gitattributes로 고정했지만, 인코딩 규칙 파일이 .editorconfig.txt로 저장돼 적용되지 않았고 그 사이 CP949 파일이 다시 섞여 하나씩 변환했습니다. 지금은 전부 UTF-8입니다.

강화 카드 UI를 이벤트로 갱신하기

강화 로직(LobbyManager)은 팀원 코드라 public으로 열지 않고 읽기 전용 Getter만 추가했습니다. 강화가 적용되면 발생하는 OnUpgradeChanged를 제가 만든 UpgradeCardUI가 OnEnable/OnDisable에서 짝지어 구독해, 패널을 껐다 켜도 중복 등록 없이 카드와 골드가 함께 갱신됩니다.

회고
  • PR은 변경 범위만 확인했고 리뷰 코멘트는 남기지 않았습니다. 다음에는 PR 템플릿과 리뷰 기준을 처음부터 두겠습니다.
  • 빌드 zip·발표 자료가 저장소에 들어갔습니다. Releases와 Git LFS를 처음부터 정하겠습니다.

같은 상태로 다시 들어가면 코루틴이 재시작돼 if (state == next) return; 가드를 뒀습니다. 1인칭 카메라에 자기 머리가 비쳐 Neck 본의 스케일을 런타임에 없앴고(HideHead), 벽에 붙거나 앉아서 버리면 아이템이 벽 너머나 바닥 속에 생성돼, 플레이어에서 손 위치까지 Linecast로 벽을 감지하면 벽 앞 0.3m로 당기고 아래로 Raycast를 쏴 바닥에 묻히지 않게 보정했습니다.

절차적 던전 위에 NavMesh 얹기

DunGen이 실행 중에 던전을 만들어 미리 구운 NavMesh를 쓸 수 없습니다. 생성 완료 이벤트를 받아 NavMeshSurface를 한 프레임 뒤 다시 굽게 했습니다. ItemSpawner는 아직 고정 2초를 기다려 같은 방식으로 바꿔야 합니다.

문 열기를 취소하고 몬스터 랜덤 스폰을 맵 끝 고정 배치로 바꿔, 남은 시간을 몬스터 AI·아이템 스폰·상호작용·게임 루프를 끝까지 완성하는 데 썼습니다.
